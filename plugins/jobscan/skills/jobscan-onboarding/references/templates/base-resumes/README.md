# Base résumés (per tier) — stable scaffolds for edit-only tailoring

Starting points, not final documents. Each holds the content stable across applications in that tier
(contact, education, publications, certifications, core skills, experience bullets). Tailoring = **edit only
the `⟪TAILOR⟫` slots** (professional summary, bullet ordering/emphasis, skills ordering, keyword
integration), then render to an ATS-safe `.docx`. Don't rebuild from scratch when a base fits.

**Tier → base file:**
- **Industry / corporate / consulting / sales** → `industry-2page.md` (tight 1–2 pp). Sales uses this base
  with a register shift noted inside.
- **Federal / government** → `federal.md` (long is correct; month/year + hours/week + supervisor fields +
  KSA-mirroring bullets).
- **State agency** → `state-agency.md` (2–4 pp; also fill the portal's structured qualification fields).
- **Academic / research** → no base; use the full master CV / `profile.md`.

**Rules baked into every base:**
- Contact verbatim from the profile; respect any minimum font size.
- **Publications: published/DOI'd only. Never list in-review work.**
- Never name a tool/skill gap as a disclaimer; honest ramp-up framing belongs in the fit assessment, not the
  résumé.
- ATS-safe: single column, standard headings, black text, simple bullets, no tables/graphics for parsed
  content.
- These are **derived from `profile.md`** — refresh them when the master changes (per its propagation note);
  don't let them become a competing source of truth.
